# 포켓몬 데스크탑 컴패니언 (Pokémon Desktop Companion)

화면 위에 항상 떠 있는 작은 창 안에서 포켓몬이 혼자 여행하고, 싸우고, 파밍하며 자라는
데스크탑 다마고치입니다. 플레이어는 언제든 돌아와서 성장 상황을 확인하고, 아이템과 기술을
정비하고, 체육관 관장·사천왕·챔피언에게 도전할 수 있습니다.

**비상업 팬 프로젝트입니다.** Pokémon 및 관련 명칭·이미지·음악의 모든 권리는 Nintendo /
Creatures Inc. / GAME FREAK inc. 에 있습니다. 이 저장소는 저작물을 포함하지 않습니다 —
아래 "에셋" 항목을 참고하세요.

---

## 개발 준비

```bash
npm install          # 의존성
npm run assets       # 에셋·데이터 내려받기 및 빌드 (최초 1회, 약 10분)
npm start            # 앱 실행
```

검사용 명령:

```bash
npm run typecheck    # tsc --checkJs --noEmit
npm test             # node:test 단위 테스트
npm run shot         # 헤드리스로 각 화면 스크린샷 (shots/)
npm run dist         # electron-builder 패키징
```

## 창

화면 면적의 약 1/16(가로·세로 각 1/4)을 차지하는 프레임 없는 항상 위 표시 창입니다.
렌더러는 항상 480×270으로 그린 뒤 창 크기에 맞춰 정수배로 확대하므로 도트가 뭉개지지
않습니다. 창 상단에 마우스를 올리면 드래그 바가 나타나고, 위치는 자동으로 기억됩니다.

## 필드

휴대기의 필드 화면을 기준으로 삼았습니다. 맵이 창을 가득 채우고 HUD는 그 위에 3세대
창틀로 얹힙니다.

필드는 **2배로 그립니다**(`FIELD_ZOOM`). 1:1로는 창에 16픽셀 타일이 30칸 들어가 — 휴대기의
두 배입니다 — 맵이 어수선한 카펫이 되고 그 위의 도트는 전부 점이 됐습니다. 2배로 하면
가로 15칸, 실제 GBA가 화면에 담던 그 프레이밍이 됩니다. 필드는 240×135 좌표로 그리고
창의 480×270으로 확대되므로, 원본 1픽셀이 항상 화면 4픽셀에 정확히 떨어집니다.

동행 포켓몬은 전투 도트가 아니라 **박스 아이콘**으로 그립니다 — 타일과 비율이 맞는 유일한
공식 도트여서, 파이리는 21×19, 망나뇽은 36×40으로 같은 맵 위에 각자의 크기로 섭니다.
박스 아이콘은 3/4 각도로 보는 이의 왼쪽을 향해 그려져 있어서, **좌우를 뒤집으면** 가는
방향을 보고 꼬리가 뒤로 갑니다.

걷기는 시간이 아니라 **이동 거리**가 굴립니다. 8픽셀마다 한 걸음, 네 박자 한 순환이고,
걸음마다 1픽셀 뜨면서 상체가 기웁니다(발은 붙어 있고 위로 갈수록 밀리는 전단). 멈추면
걸음도 그 자리에서 멈춥니다.

동행 포켓몬·트레이너·나무열매 나무는 **1.5배**로 그립니다(`ACTOR_SCALE`). 16픽셀 타일에
맞춰 그려진 도트라 1:1로는 창 안에서 엄지손톱만 했습니다. 길에 떨어진 볼만은 반대로
줄입니다 — 가방 목록용 아이콘이라 땅에 놓으면 포켓몬만 합니다. 트레이너는 시트의 서쪽
프레임 그대로여서 다가오는 포켓몬을 마주 봅니다.

**걷는 줄은 맵이 정합니다.** 파이프라인이 각 맵의 충돌 정보를 읽어 발밑과 그 위 두 줄이
모두 지나갈 수 있는 행을 고르고, 그 값을 `areas.json` 의 `groundY` 로 내보냅니다. 화면
높이의 62% 같은 고정값으로는 포켓몬이 나무를 뚫고 걷는 맵이 나왔습니다.

### 이벤트의 시계

1분에 한 번 이벤트를, 10분에 한 번 에리어 교체를 굴립니다. **시계는 길 위에서 벌어지는
일과 무관하게 돌기 때문에**, 앞의 이벤트가 아직 끝나지 않은 채 다음 차례가 돌아올 수
있습니다. 그때는 차례를 버리지 않고 **몇 초 뒤로 미룹니다**(`EVENT_RETRY_MS`) — 타이머를
통째로 되감으면 포켓몬센터를 구경한 대가로 1분을 더, 혹은 같은 에리어에서 10분을 더
기다리게 됩니다.

센터 방문은 **문 애니메이션 한 벌 + 지나가기 한 번**으로 끝납니다. 대본을 다 읽은 뒤에도
계속 "지나가는 중"을 돌려주고 있어서 이벤트가 영영 끝나지 않았고, 그 뒤로는 어떤
이벤트도 에리어 교체도 일어나지 않았습니다.

## 전투

전투는 맵 위가 아니라 **전투 배경** 앞에서 벌어집니다. 에메랄드의 배경은 4bpp 타일 시트 ·
32×32 타일맵 · 팔레트로 이뤄진 평범한 GBA 배경 레이어라, 파이프라인이 필드와 똑같은
240×135 크기의 PNG 한 장으로 합성합니다. 어느 배경이 나오는지는 지역의 지형 태그가
정합니다 — 동굴이면 동굴, 바다면 물가입니다.

같은 타일에 팔레트만 바꿔 넣는 것이 원작의 방식이어서, 체육관 관장전은 관장실
팔레트로, 사천왕과 챔피언은 각자의 방(시드니·피비·글라시아·드레이크·윤진) 팔레트로
나옵니다.

### 메시지 창

엔진은 한 턴을 통째로 계산하고 화면이 그 로그를 한 줄씩 재생합니다. 줄은 **원작의 순서와
문장** 그대로입니다 — 만난 줄("앗! 야생 …가 나타났다!" / "…가 승부를 걸어왔다!"), "가라!
…!", 기술 이름, 급소·효과 판정, 그리고 능력 변화와 상태이상의 뒷말.

만난 줄은 **전투 화면에서만** 나옵니다. 필드에서 토스트로 한 번, 전투 시작 줄로 또 한 번
— 같은 문장이 화면에 둘씩 떠 있던 것이 "이벤트가 두 번 출력된다"의 정체였습니다.

**쓰러진 줄은 로그 항목이 들고 온 포켓몬의 이름을 씁니다.** 로그는 턴이 끝난 뒤에 재생되고,
마지막 상대가 쓰러진 시점에 엔진의 `battle.foe` 는 이미 비어 있습니다. 그래서 항목에
포켓몬 자체를 실어 보냅니다 — 이름 없는 "은(는) 쓰러졌다!" 와, 포획 대기줄에 아무것도
들어가지 않던 문제가 같은 원인이었습니다.

**능력 변화는 이펙트와 문장이 함께 갑니다.** 오른 쪽에는 초록 갈매기표가 도트를 타고
올라가고 내린 쪽에는 빨간 갈매기표가 내려가며, 문장은 단수에 따라 "올라갔다 / 크게
올라갔다 / 매우 크게 올라갔다"로 갈립니다. 이미 한계면 "더 이상 올라가지 않는다!" 를
말합니다 — 아무 일도 없었던 것처럼 넘어가지 않습니다.

**명중률과 회피율**은 기술 데이터가 `accuracy` · `evasion` 으로 길게 적고 명중 판정은
`acc` · `eva` 를 읽습니다. 그 사이가 이어져 있지 않아 모래뿌리기와 그림자분신이 아무
일도 하지 않고 있었습니다.

## 포켓몬 리그

도전 화면은 전투 배경이 아니라 **사람이 서 있는 그 방**을 깝니다 — 에메랄드의 사천왕 방
다섯 곳(`EverGrandeCity_*Room`)을 실제 실내 맵 그대로 렌더해서, 그 방의 주인이 서 있는
칸을 중심으로 창 크기만큼 잘라냅니다. 싸우는 자리가 아니라 문간에 서서 들어갈지 정하는
자리라서입니다.

사천왕 넷과 그 뒤의 챔피언은 **한 게임의 사람들이라 묶음으로 움직입니다.** 리그에 들어설
때마다 저장된 여덟 묶음(석영·호연·신오·하나·칼로스·알로라·팔데아·블루베리) 중 하나가
통째로 뽑히고, 그 도전이 끝날 때까지 유지됩니다. 파티는 원작 게임의 실제 로스터이고
레벨만 도전자에 맞춰 조정됩니다.

포켓몬은 서로를 마주 봅니다. 앞면 도트는 보는 이의 왼쪽을, 뒷면 도트는 오른쪽을 향해
그려져 있어서 **둘 다 뒤집지 않는 것**이 맞고, 뒷면 도트가 없는 종만 앞면 도트를 뒤집어
세웁니다. 창 위로 머리가 잘리는 큰 종은 발밑에서 화면 위까지의 높이에 맞춰 줄입니다.

## 포획

**야생 포켓몬은 쓰러뜨린 다음에 잡습니다.** 이기면 그 자리에서 포획 화면이 열립니다 —
가운데 선 상대, 아래에 실제로 들고 있는 볼과 각 볼의 진짜 확률, 구석에 남은 세 번의 기회.
볼이 하나도 없으면 화면을 열지 않고 **포획 대기줄**로 보냅니다.

대기줄은 HUD 오른쪽 위에 "포획 대기" 라는 이름표와 함께 섭니다. 기회를 놓쳤거나 화면을
닫아 둔 포켓몬이 최대 다섯 마리까지 기다리고, 아이콘을 누르면 다시 포획 화면이 열립니다.
세 번을 다 던져 **도망친** 포켓몬만 줄에서 사라집니다 — 취소한 포켓몬은 제자리로
돌아갑니다. 박스가 가득 차 있으면 잡은 것도 넣을 곳이 없으므로 줄에 그대로 남습니다.

대기줄은 저장되지 않습니다. 그 순간의 제안이지, 며칠 뒤에 돌아와서 처리할 목록이
아니기 때문입니다.

## 소리

음악은 MIDI를 노트 이벤트로 줄여 신시사이저로 연주합니다. **팡파르는 음악이 아니라 효과음
채널을 씁니다** — 레벨업·포획·회복·뱃지·승리가 전부 그렇습니다.

원작 카트리지가 그렇듯 **팡파르가 울리는 동안 음악은 비켜섭니다.** 엔진은 "지금 흘러야
하는 곡"(`wanted`)을 연주 중인 곡과 따로 들고 있어서, 팡파르가 끝나면 그 곡이 돌아옵니다.
전투가 끝나고 필드로 돌아가는 순간처럼 **팡파르와 곡 교체가 같은 프레임에 일어나도**
돌아오는 것은 새 곡입니다 — `wanted` 는 곡을 불러오기 전에 먼저 정해지기 때문입니다.

전투·리그·메뉴처럼 위에 얹히는 화면은 나갈 때 **원래 곡을 다시 요청합니다.** 이것이
없어서 전투가 끝난 뒤에도 전투 음악이 길 위에서 계속 반복됐습니다.

## 특성

특성은 처음부터 세이브에 들어 있었지만 아무 일도 하지 않았습니다. 지금은 **314개 중
245개를 엔진이 실제로 읽습니다** — 능력치 배수(파워풀허브·엽록소·근성), 데미지 증감
(철주먹·강한턱·두꺼운지방·멀티스케일), 타입 무효와 흡수(부유·축전·저수·타오르는불꽃),
접촉 반격(정전기·불꽃몸·까칠한피부), 상태이상 차단(면역·불면·수의베일), 명중·급소·선공
(복안·색안경·짓궃은마음), 등장 시 발동(위협·다운로드·트레이스), 턴 끝 처리(가속·우천
시·포이즌힐), 능력 변화 방어와 반격(클리어바디·심술꾸러기·오기·미러아머·천진), 쓰러뜨린
뒤(자기과신·비스트부스트), 타입 변경(변환자재·변색·배짱), 지닌 물건(먹보·숙성·나쁜손버릇·
곡예·긴장감), 재앙 4종까지입니다. 나머지는 포켓몬 화면이 **"이 게임에서는 아직 효과가
없습니다"** 라고 스스로 밝힙니다 — 아이템이 그렇게 하는 것과 같은 방식입니다.

남은 69개는 **이 게임에 그 시스템이 없어서** 붙일 수 없는 것들입니다 — 폼체인지 21개
(기분파·배틀스위치·고대활성…), 아군이 필요한 더블배틀용 20개(플러스·다크오라·무희…),
교체가 필요한 14개(자연회복·재생력·개미지옥…), 특성을 바꾸거나 지우는 수단이 필요한
4개(미라·화학변화가스…), 그리고 무게·픽업·알림뿐인 나머지입니다.

야생에서 만나는 포켓몬은 **숨겨진 특성을 포함한 보유 특성 전부에서 똑같은 확률로**
뽑습니다. 원작은 숨겨진 특성을 레이드와 특성패치 뒤에 두지만 이 게임에는 둘 다 없어서,
길에서 만나는 포켓몬이 유일한 출처이기 때문입니다. 트레이너가 내보내는 포켓몬은 원작대로
일반 특성에서만 뽑습니다.

진화할 때는 특성 이름이 아니라 **특성 슬롯**을 물려받습니다. 이브이의 2번 슬롯(적응력)이
샤미드의 2번 슬롯(촉촉바디)이 되는 식으로, 원작이 하는 것과 같습니다.

## 상태와 필드에 놓이는 것들

세이브에 적히는 상태(화상·독·마비·잠듦·얼음)와 달리 **전투가 끝나면 사라지는 것들**은
포켓몬이 아니라 전투원 쪽에 붙습니다 — 랭크 변화가 그렇듯이, 원작도 그렇게 들고 있습니다.

- **혼란** — 2~5턴, 1/3 확률로 자기 자신을 위력 40 무속성 물리로 때립니다(7세대 이후 확률).
- **헤롱헤롱** — 서로 성별이 달라야 걸리고, 절반의 확률로 움직이지 못합니다. **성별**은
  종족의 `genderRate`(8분의 몇이 암컷인가)에서 굴립니다 — 메타몽은 무성, 럭키는 전부 암컷.
- **설치 기술** — 압정(3겹)·독압정(2겹)·스텔스록·끈적끈적네트. 동행은 교체하지 않으니
  발밑에 깔린 것은 터지지 않지만, **트레이너는 다음 포켓몬을 내보냅니다** — 그때마다 앞
  포켓몬을 위해 깔아 둔 것 위로 걸어 나옵니다. 스텔스록은 바위 상성을 곱하고, 압정과
  거미줄은 땅에 선 포켓몬만, 독압정은 땅에 선 독타입이 도착만으로 치워 버립니다.
  두꺼운장갑은 전부 밟지 않고 넘어갑니다.
- **방어 기술** — 방어·판별·니들가드·독압정가드·킹실드·블로킹·실크트랩·화염의울타리.
  연속으로 쓸수록 성공률이 1/3씩 줄고, 접촉으로 막힌 쪽은 그 기술이 매기는 값을 냅니다
  (니들가드 1/8, 킹실드 공격 -1, 블로킹 방어 -2…). 보이지않는주먹과 관통드릴은 뚫습니다.
- **기술 봉인** — 사용금지(4턴)·도발(3턴)·앙코르(3턴)·트집. 걸리면 자동전투가 쓸 수 있는
  기술 목록에서 빠지고, 앙코르는 반대로 그 기술만 남깁니다. 멘탈허브가 한 번에 풀어 줍니다.

## 기술 분류

기술은 타입과 분류(물리·특수·변화)만으로는 부족합니다. 정전기는 **접촉** 기술에만,
방탄은 **구슬** 기술에만, 방음은 **소리** 기술에만, 방진고글은 **가루** 기술에만
반응하기 때문입니다. PokeAPI에는 이 분류가 없고, 해체된 원작 소스는 그 세대가 알던
플래그만 들고 있어서 3세대 덤프로는 어떤 기술이 구슬인지 알 수 없습니다. 그래서
파이프라인이 **Pokémon Showdown의 기술 표**에서 이것만 읽어 옵니다 — 같은 평범한
HTTPS 호스트에서 파일 하나, 다른 어디에도 없는 한 가지를 위해서입니다.

게임이 싣는 분류는 엔진이나 화면이 실제로 읽는 14가지입니다 — 접촉 · 펀치 · 깨물기 ·
베기 · 소리 · 가루 · 구슬 · 파동 · 바람 · 춤 · 모으기 · 재충전 · 해동 · 회복. 937개 기술
중 432개가 하나 이상을 답니다. 포켓몬 화면의 기술 칸이 타입 옆에 함께 보여 줍니다.

**모으기**와 **재충전**은 분류에 그치지 않고 턴을 바꿉니다. 솔라빔은 한 턴 모았다가 다음
턴에 나가고(쾌청이면 그냥 나갑니다), 파괴광선은 쏜 다음 턴을 반드시 쉽니다. 파워하브는
모으는 턴을 통째로 사 줍니다.

## 필드 효과

자동전투 화면에는 처음부터 **필드 기술** 항목과 **"필드가 없을 때"** 조건이 있었지만,
가리킬 것이 없었습니다. 날씨도 필드도 없었으니 조건은 언제나 참이었고 쾌청은 아무것도
하지 않는 변화 기술이었습니다.

이제 셋이 있습니다. **날씨**(쾌청·비·모래바람·싸라기눈·설경)는 판 전체를 덮고 타입의
값을 바꿉니다. **필드**(일렉트릭·그래스·미스트·사이코)는 땅을 덮으므로 **땅에 서 있는
포켓몬에게만** 닿습니다 — 비행 타입, 부유, 풍선을 든 포켓몬은 그 위에 있습니다.
**장막**(리플렉터·빛의장막)은 판이 아니라 한쪽 편의 것이라, 그쪽으로 오는 한 분류의
데미지를 반으로 줄입니다. 기본 5턴이고, 부른 쪽이 해당 바위(뜨거운바위·축축한바위…)나
그라운드코트·라이트클레이를 들고 있으면 8턴입니다.

날씨는 데미지만 바꾸지 않습니다 — 모래바람과 싸라기눈은 턴 끝에 깎고, 그래스필드는
채워 주고, 번개와 폭풍은 비에서 반드시 맞고 쾌청에서 명중률이 절반이 되며, 광합성은
쾌청에서 최대 HP의 2/3, 다른 날씨에서는 1/4을 회복합니다. 얼음 상태는 쾌청에서 걸리지
않고, 미스트필드 위에서는 어떤 상태이상도 걸리지 않습니다.

**어떤 곳은 처음부터 그 날씨 아래에 있습니다.** 맵 파일에도 날씨 필드가 있지만 그것이
아닙니다 — 에메랄드는 야외 맵 거의 전부를 `WEATHER_SUNNY`(그냥 대낮)로 적어 두고 111번
도로의 모래바람이나 119번 도로의 비는 맵의 스크립트가 겁니다. 그래서 하늘은 **에리어
태그**에서 옵니다. 119번 도로는 비가 오니까 `rain`, 111번 도로는 모래바람이니까 `desert`,
해변동굴은 얼음투성이라 `ice` 라고 적혀 있던 그 태그입니다. 그곳의 전투는 그 날씨로
시작하고, 아무도 부른 것이 아니므로 끝나지도 않습니다.

## 이로치

**출현 확률은 원작 그대로 1/4096 입니다.** 금·은부터 블랙·화이트까지가 1/8192, X·Y부터가
1/4096이고, 이 게임은 종족값도 기술 배치도 타입 상성도 전부 최신 세대를 따르므로 여기서도
그렇게 합니다. 다른 보정은 없습니다 — 빛나는부적도 국제결혼도 이 게임에는 없습니다.

이로치는 **다른 색으로 칠한 것이 아니라 다른 그림**입니다. 종마다 손으로 고른 팔레트라
파란 갸라도스에서 빨간 갸라도스를 계산해 낼 방법이 없습니다. 그래서 파이프라인이 앞면 ·
뒷면을 같은 출처에서 한 번 더 내려받아 `front-shiny.png` · `back-shiny.png` 로 나란히
둡니다. 트리밍은 그림마다 따로 하므로 매니페스트도 자기 크기를 따로 들고 있습니다 —
팔레트가 다르면 가장자리의 투명한 여백도 늘 같지는 않기 때문입니다.

**박스 아이콘만은 이로치 판이 공개되어 있지 않습니다.** 대신 같은 그림 두 장 — 평범한
앞면 도트와 이로치 앞면 도트 — 을 겹쳐 **어느 색이 어느 색이 되었는지 읽어 냅니다.** 그
대응표를 박스 아이콘에 통과시키면 필드를 걷는 동행도 제 색으로 걷습니다.

아이콘은 전투 도트와 다른 손이 그린 것이라 같은 부위라도 색이 바이트 단위로 같지는
않습니다. 그래서 거리는 RGB가 아니라 **색상(hue)과 밝기**로 재고 채도는 깎아서 봅니다 —
아이콘 쪽이 훨씬 진하게 칠해져 있어서 RGB로 재면 배가 배에 붙지 않고 엉뚱한 음영에
붙습니다. 회색끼리는 색상이 없으므로 밝기로만 맞춥니다.

**완벽하지는 않습니다.** 색을 색에 대응시키는 방식이라, 한쪽 그림에서 서로 다른 두 부위가
같은 색인 종은 갈라놓을 수 없습니다 — 파이리는 아이콘의 몸통 주황이 전투 도트의 꼬리
불꽃 주황과 같은 색이라, 이로치 아이콘에 노란 기가 돌긴 해도 몸통은 주황으로 남습니다.
두 앞면 도트가 서로 다른 출처에서 왔으면 같은 그림 두 장이 아니므로 아예 대응표를 만들지
않고, 그 17종은 필드에서 평소 색으로 걷습니다.

이로치는 전투 시작 줄, 포획 화면, 포켓몬 화면, 박스, HUD, 세이브 슬롯 어디에서나 **★**
로 표시됩니다.

## 자동전투

싸움은 방치해도 굴러가야 하므로, 무엇을 쓸지는 **기술 사용 순서**와 **기술 종류별 사용
조건** 둘로 정합니다. 순서 칸에 직접 넣은 기술이 먼저 나가고, 그게 떨어지면 종류별 조건이
맞는 기술 중에서 고릅니다.

조건은 `미사용 · 항상 · 전투 시작 시 · 상대가 멀쩡할 때 · 상대가 상태이상일 때 · 필드가
없을 때 · 체력 2/3·1/2·1/3·1/4 이하` 이고, **미사용도 조건의 하나**입니다 — 켜고 끄는
체크박스와 언제 쓸지 정하는 칸은 결국 같은 결정이라 하나로 합쳤습니다.

공격 기술끼리는 경쟁하지 않습니다. 순서를 지정하지 않은 채 공격 기술을 여럿 들고 있으면
**기대 데미지가 가장 높은 하나**를 씁니다(타입 상성·위력·명중률·연속타를 곱한 값). 불꽃세례와
몸통박치기 사이에서 매 턴 주사위를 굴리는 쪽이 오히려 이상하기 때문입니다.

## 아이템

**이 게임이 언젠가 다룰 수 있는 것은 남기고, 영영 다룰 수 없는 것만 버립니다.** PokeAPI가
아는 2150개 중 1376개를 빌드 단계에서 버리고 774개를 남깁니다.

버리는 기준은 "지금 동작하는가"가 아니라 **그 아이템이 속한 시스템을 이 게임이 가질 수
있는가**입니다. 민트는 성격을, 캡슐은 특성을, 포인트업은 PP를, 영양제는 노력치를, 타입보호
나무열매는 타입 상성을 건드립니다 — 전부 세이브가 이미 들고 있는 값이라, 엔진이 아직 읽지
않을 뿐 붙이면 동작합니다. 그래서 남깁니다. 반대로 메가스톤·Z크리스탈·다이맥스 크리스탈·
테라피스는 폼체인지, 볼 재료와 기술머신 재료는 제작, 카레·샌드위치·포켓블록용 나무열매는
요리, 자전거와 낚싯대는 마을이 있는 세계의 물건이라 버립니다. 이름으로 따로 버리는 것은
**학습장치**(경험치를 파티원끼리 나누는데 동행이 한 마리)와 돈 관련 소수입니다.

남은 774개 중 **684개는 엔진이 실제로 읽고**, 90개가 아직 기다립니다. 가방의 조사 화면이
"이 게임에서는 아직 효과가 없습니다"라고 스스로 밝히므로, 써 보고 나서야 알게 되지는
않습니다. 남은 93개는 교체(탈출보터·빨간카드)·헤롱헤롱(붉은실)·친밀도(평온의종) 처럼
이 게임이 아직 갖고 있지 않은 시스템의 것들입니다.

효과는 설명문이 아니라 **PokeAPI의 effect 텍스트**에서 읽습니다. 플레이어가 보는 설명은
"HP를 조금 회복한다"처럼 일부러 모호하지만, 같은 아이템의 effect 는 "Restores 20 HP",
"Restores 10 PP for one move", "Raises Attack effort" 처럼 정확합니다. 그래서 상처약의 20,
이상해열매의 최대 HP 1/4, 에테르의 PP 10, 단백질의 노력치 10, 이상한사탕의 레벨 1이 코드에
숫자로 적히지 않고 데이터에서 나옵니다.

지닌 채로 작동하는 것들도 같은 방식으로 구현되어 있습니다 — 먹다남은음식(매 턴 최대 HP
1/16 회복), 검은해도지(독타입이면 회복, 아니면 1/8 피해), 구애머리띠·구애안경·구애스카프
(해당 능력치 1.5배 + 기술 하나에 고정), 목탄 같은 타입 강화 도구와 플레이트(해당 타입 20%),
파워리스트 계열(물리/특수 10%), 달인의띠(효과가 굉장할 때 20%), 생명의구슬(30%, 최대 HP
10% 소모), 조개껍질방울(입힌 피해의 1/8 회복), 초점렌즈(급소율 +1랭크), 기합의띠(HP 만탱일
때 1로 버팀)·기합의머리띠(10% 확률), 선제공격손톱(18.75% 확률로 선공), 행운의알(경험치
1.5배), 진화의휘석(미진화 종족 방어·특방 1.5배), 돌격조끼(특방 1.5배, 변화 기술 사용 불가),
파워앵클(노력치 2배, 스피드 절반).

## 도구를 누가 들고 있는가

**야생 포켓몬의 도구는 원작의 그 로직 그대로입니다.** 에메랄드의 `SetWildMonHeldItem` 은
100면 주사위를 굴려 45 미만이면 아무것도, 95 미만이면 **흔한 칸**, 그 위면 **드문 칸**을
쥐여 줍니다. 선두 포켓몬(여기서는 동행)이 **복안**이면 그 두 경계가 20과 80으로 내려가
훨씬 자주 나옵니다. 두 칸이 같은 도구면 100% 들고 나옵니다 — 원작이 "항상"을 적는 방식이
그것입니다. 트레이너전에서는 이 함수가 아예 돌지 않습니다.

두 칸은 PokeAPI가 버전별 `rarity` 로 같은 표를 싣고 있어서(흔한 칸 50, 드문 칸 5, 항상
100) 거기서 읽어 옵니다. 최신 버전 것이 이기고, 이 게임이 싣지 않는 도구(별의모래·큰진주
같은 매각용)를 가리키는 칸은 비웁니다. **1025종 중 343종**이 표를 들고 있습니다.

**트레이너의 도구는 원작이 굴리지 않습니다** — 파티가 손으로 적혀 있고 도구도 거기 적힙니다.
그래서 규칙을 지어내는 대신 에메랄드의 파티 데이터를 세었습니다: 일반 트레이너 770 파티의
포켓몬 1487마리 중 **도구를 든 것은 55마리(3.7%)**, 그마저 대부분 오랭열매입니다. 반면
**체육관 관장과 사천왕·챔피언은 마지막에 내보내는 에이스가 반드시 열매를 듭니다**(초반엔
오랭, 뒤로 갈수록 자몽·초푸열매). 이 게임도 그대로 합니다.

그래서 이제 **상대도 도구를 씁니다** — 야생 피카츄가 전기구슬을 들고 나오고, 관장의 에이스가
체력이 깎이면 자몽열매를 먹습니다. 열매 판정은 양쪽 모두에게 돌아갑니다.

**기다리고 있던 것들도 이제 대부분 동작합니다.**

- 가방에서 쓰는 것 — 민트(성격 교체), 특성캡슐(일반 특성 맞바꾸기)·특성패치(숨겨진 특성),
  은왕관·금왕관(개체값 최대화), 포인트업·포인트맥스(기술 PP 상한 20%·60%), 날개(노력치
  1씩), 경험사탕, 떡, 마비치료·화상치료처럼 설명문을 읽어 내지 못하던 몇 가지.

## 가방

**아이템은 그 아이템이 하는 일로 메뉴가 정해집니다.**

| 포켓 | 메뉴 |
| --- | --- |
| 회복 | 사용 · 조사 · 버리기 |
| 도구 · 나무열매 | **장착** · 조사 · 버리기 |
| 볼 | 조사 · 버리기 |
| 기술머신 | 사용(가르치기) · 조사 · 버리기 |

먹다남은음식은 가방 안에서 아무 일도 하지 않습니다 — 들고 있어야 하는 물건이라 도구와
나무열매는 **장착**을 내놓습니다. 들고 있던 것은 가방으로 돌아갑니다. 예외는 지금 동행
포켓몬이 기다리고 있는 **진화의 돌**로, 그것만은 들리는 것이 아니라 쓰는 것이라 사용도
함께 나옵니다. 볼은 포획 화면에서 던지는 것이므로 가방 메뉴에 사용이 없습니다.

**기술머신의 설명은 기술의 설명입니다.** 기술머신 자신의 설명문은 세대에 따라 모든
기술머신이 같은 한 문장이거나 기술 설명이거나 해서 일정하지 않은데, 플레이어가 고르는
것은 기술이기 때문입니다. 기술 이름 · 타입 · 분류 · 위력 · 명중 · PP · 기술 설명을 언제나
같은 자리에 같은 순서로 보여 줍니다.

동행 포켓몬이 배울 수 없는 기술머신을 쓰면 원작처럼 **"…은(는) …을(를) 배울 수 없다!"**
라고 이름을 대고 거절합니다.

들려준 물건은 **포켓몬 탭의 "지닌 물건"** 을 눌러 되돌려 받습니다 — 장착의 반대쪽이
없으면 한번 들린 물건은 바꿀 수만 있고 뺄 수는 없게 됩니다.

**포켓몬 탭에서는 기술을 눌러 설명을 봅니다.** 누르면 그 칸 아래에 기술 카드가 펼쳐지고,
바꾸려면 카드의 버튼을 누릅니다 — 무엇을 하는 기술인지 보려다 기술을 잃어버리지 않도록
읽기와 바꾸기를 두 단계로 나눴습니다. 빈 칸은 볼 것이 없으므로 곧장 목록이 열립니다.

가방의 마지막 탭 **사용 설정**에는 가방을 열지 않아도 굴러가는 두 가지가 있습니다.

- **나무열매 자동 보충** — 1~3순위를 정해 두면 전투가 끝났을 때 아무것도 들고 있지 않은
  포켓몬 손에 순서대로 찾아 들려줍니다. 순위는 비워 둘 수 있습니다(미지정). 들고 있는
  나무열매는 체력이 절반 이하로 떨어지면 스스로 먹습니다 — 그래서 보충이 필요합니다.
- **회복 아이템 사용** — 조건(미사용·체력 2/3·1/2·1/3·1/4 이하)이 맞으면 **그 턴의 행동
  대신** 아이템을 씁니다. 원작에서 가방을 여는 턴과 같습니다. 쓸 아이템을 지정하지 않으면
  깎인 만큼을 채울 수 있는 가장 작은 것을 고릅니다. 전투 화면의 **가방** 버튼으로 직접
  던질 수도 있고, 그 역시 다음 행동을 대신합니다.

회복 이벤트는 길 위에 **포켓몬센터**가 서고, 동행 포켓몬이 문 앞까지 걸어가 문이 열리면
들어갔다가 5초 뒤 다시 나오는 연출로 진행됩니다. 센터 건물은 따로 그려진 스프라이트가
없어서 — 마을 맵의 일부입니다 — 파이프라인이 오래달마을을 통째로 렌더한 뒤 **안으로
들어가는 워프 위치**를 문으로 삼아 건물만 오려냅니다. 문은 원작이 쓰는 3프레임 개폐
애니메이션(`graphics/door_anims/poke_center.png`)을 그 문 자리에 덮어 그립니다.

안에 있는 동안 체력·PP가 모두 차고 **레벨에 맞는 상처약 5개**를 받습니다(20/40/60 레벨을
경계로 상처약·좋은 상처약·고급 상처약·최고 상처약). 던질 물건이 어디선가는 나와야 하기
때문입니다.

포켓몬이 쓰러지면 잃는 것은 **그 야생 포켓몬뿐**입니다 — 이기지 못한 야생 포켓몬에게는
볼을 던질 수 없으니 포획 기회가 사라집니다. 트레이너전은 잃는 것이 없습니다. 어느 쪽이든
**다음 이벤트는 회복으로 고정**되어, 쓰러진 포켓몬은 곧장 쉼터로 향합니다.

## 구조

뿌리에는 **실행되는 것**과 도구가 뿌리에 있기를 요구하는 파일만 둡니다. 나머지는 성격에
따라 `app/` · `dev/` · `data/` 셋 중 하나로 들어갑니다.

```
package.json         npm 이 뿌리에서만 읽음
package-lock.json    npm 이 뿌리에서만 읽음
README.md            GitHub 첫 화면
.gitignore           git 이 뿌리에서만 읽음
.github/             GitHub Actions 가 이 경로만 봄

app/                 ← 실행되는 본체 (패키지에 들어가는 유일한 코드)
  main/              Electron 메인 프로세스 (창, 세이브, 설정, 프로토콜)
  preload/           렌더러 ↔ 메인 브리지
  renderer/          게임 (core · engine · render · scenes · ui)
  shared/            메인·렌더러·파이프라인이 함께 쓰는 상수

dev/                 ← 개발용. 패키지에 들어가지 않음
  tools/             에셋·데이터 파이프라인 (lib · fetch · build)
  test/              단위 테스트
  build/             패키징 리소스 (아이콘)
  docs/              파이프라인이 출력하는 참고 문서
  tsconfig.json

data/                ← 데이터
  authored/          손으로 저술 (관장/사천왕/챔피언, 트레이너 계급, i18n · 언어 시트)
  generated/         파이프라인 산출물 (gitignored)

assets/              생성 에셋 (gitignored)
dist/                패키지 산출물 (gitignored)
```

## 파이프라인 단계

`npm run assets` 는 아래 단계를 순서대로 실행합니다. `--only <step>` 으로 하나만,
`--sample` 로 40종만 돌려 빠르게 확인할 수 있습니다.

| 단계 | 하는 일 | 산출물 |
| --- | --- | --- |
| `dex` | 종족값·기술(분류 포함)·아이템·특성·타입 상성·기술머신 (언어 시트에 적힌 모든 언어의 공식 명칭/설명 포함) | `data/generated/{species,moves,items,abilities,machines,types}.json` |
| `sprites` | 포켓몬 1025종의 애니 스프라이트 스트립(평범·이로치)·박스 아이콘·울음소리 | `assets/pokemon/`, `assets/cries/`, `sprites.json` |
| `items` | 아이템 아이콘, 볼 등급별 희귀도 티어 | `assets/items/`, `item-tiers.json`, `dev/docs/item-rarity.md` |
| `actors` | 트레이너 정면/필드 도트, 나무열매 나무, 아이템 볼 | `assets/trainers/`, `assets/props/`, `actors.json` |
| `areas` | 공식 맵 30곳을 시간대 5종의 심리스 스크롤 배경으로 렌더 (걷는 줄 포함) | `assets/areas/`, `areas.json` |
| `battle` | 전투 배경 17종(지형·체육관·사천왕 방), 리그 방 5곳, 체육관 뱃지 8종 | `assets/battle/`, `assets/rooms/`, `assets/badges/`, `battle.json` |
| `audio` | 에리어·전투·연출 BGM 36곡을 노트 이벤트 JSON으로 변환 | `assets/bgm/`, `bgm.json` |
| `verify` | 매니페스트와 실제 파일이 맞는지 교차 검증 | — |

전체 산출물은 약 95MB (스프라이트 66MB · 울음소리 17MB · 배경 4MB · 아이템 3MB ·
BGM 2MB · 트레이너 1MB · 전투 배경과 뱃지 1MB) + 데이터 4MB 입니다. 스프라이트가 예전의
두 배인 것은 **이로치 판을 함께 굽기 때문**입니다 — 다시 칠하는 것이 아니라 다른 그림이라
받아 두는 수밖에 없습니다.

## 파이프라인 라이브러리

`dev/tools/lib/` 의 모듈은 외부 네이티브 의존성 없이 필요한 포맷만 직접 다룹니다.

- `png.mjs` — PNG 디코더/인코더 (1·2·4·8bpp 인덱스, 그레이, RGB, RGBA)
- `gif.mjs` — 애니메이션 GIF 디코더 (LZW, 인터레이스, disposal 처리)
- `gba-gfx.mjs` — GBA 4bpp 타일셋 · JASC 팔레트 · 메타타일 · 맵 블록데이터 렌더러
- `maps.mjs` — 맵 하나를 픽셀로: 레이아웃 색인 · 타일셋 캐시 (`areas` 와 `battle` 이 함께 씀)
- `midi.mjs` — SMF 파서 → 절대시간 노트 이벤트
- `image.mjs` — 크롭 · 미러 · 심리스 스트립 · 시간대 컬러 그레이딩 · 프레임 리샘플 · 팔레트 대응표
- `http.mjs` — 디스크 캐시 · 재시도 · 동시성 제한 다운로더
- `poke.mjs` — PokeAPI 레코드에서 언어별 공식 명칭/최신 설명을 뽑는 헬퍼

## 배포 · 패키징

`npm run dist` 은 `electron-builder` 로 현재 OS용 패키지를 만듭니다. 대상은
Windows(zip), macOS(dmg, x64·arm64), Linux(AppImage)이며 산출물은 `dist/` 에 떨어집니다.
컨테이너에서 리눅스만 빨리 확인하려면 `npm run dist:linux` 를 쓰세요.

윈도우는 설치본 없이 zip만 냅니다. 설치 프로그램은 서명이 없으면 경고가 한 겹 더 붙고,
어차피 세이브와 설정을 앱 바깥에 두기 때문에 압축을 푸는 것 이상으로 해줄 일이 없습니다.

에셋은 저장소에 없지만 **패키지 안에는 들어갑니다.** `assets/` 와 `data/` 를
`extraResources` 로 복사하므로 설치본 하나만 받으면 추가 다운로드 없이 실행됩니다.
`app/main/paths.mjs` 가 `process.resourcesPath` 를 먼저 보고 없으면 저장소 경로로
되돌아가므로, 개발 실행과 패키지 실행이 같은 코드로 동작합니다. 세이브와 설정은 패키지
바깥의 `app.getPath('userData')` 에 저장되므로 업데이트해도 남습니다.

아이콘은 `npm run icon` 이 `dev/build/icon.png` 를 그립니다. 저장소에 커밋되는 유일한 그림이며,
포켓몬 저작물이 아닌 자체 도형입니다.

GitHub Actions 워크플로는 세 개입니다.

| 워크플로 | 시점 | 하는 일 |
| --- | --- | --- |
| `check.yml` | 모든 푸시·PR | 에셋 빌드 → `npm run typecheck` → `npm test` |
| `build.yml` | `v*` 태그 푸시 (또는 수동) | 3개 OS 매트릭스로 패키징 → **드래프트 릴리스**에 업로드 |
| `itch.yml` | `build.yml` 성공 후 | `ITCH_API_KEY`·`ITCH_TARGET` 이 설정된 경우에만 `butler push` |

에셋 다운로드는 `dev/tools/**` 와 `package-lock.json` 해시를 키로 `actions/cache` 에 캐시되므로,
게임 코드만 바꾼 빌드는 내려받기를 건너뜁니다. 서명 인증서가 없어 macOS 빌드는 서명되지
않은 상태로 나갑니다(첫 실행 시 Gatekeeper 우회 필요).

릴리스 절차:

```bash
npm version 0.1.1        # package.json 버전 갱신 + 태그
git push --follow-tags   # build.yml 이 태그를 받아 드래프트 릴리스 생성
```

## 언어

설정의 **언어** 탭에서 언어를 고르면 화면 문자열은 물론 포켓몬·기술·아이템·지역명까지
그 언어의 공식 명칭으로 즉시 바뀝니다. 지원 언어는 코드가 아니라 시트 한 장에 적혀 있습니다.

```
data/authored/i18n/
  languages.json     지원 언어 시트 — 아래 세 곳이 모두 이 파일만 읽습니다
  ko.json            화면 문자열
  en.json
```

| 열 | 뜻 |
| --- | --- |
| `code` | 설정에 저장되는 값이자 생성 데이터에서 그 언어의 이름이 담기는 키 |
| `label` | 설정 화면에 표시할 이름 (그 언어로 적습니다) |
| `strings` | 화면 문자열 파일 (`data/authored/` 기준 경로) |
| `source` | PokeAPI 언어 이름. 파이프라인이 공식 명칭·설명을 여기서 가져옵니다 |
| `grammar` | 문자열에 필요한 문법 도우미 (`korean` = 조사 일치) |
| `fallback` | 번역이 빠졌을 때 대신 읽을 언어 |
| `default` | 새로 설치했을 때 시작할 언어 |

**언어를 추가하려면** 시트에 한 줄을 넣고 `strings` 가 가리키는 파일을 두면 됩니다.
메인 프로세스(설정 검증)·렌더러(화면 문자열)·에셋 파이프라인(공식 명칭 수집)이 모두 같은
시트를 읽으므로 고칠 코드는 없습니다. 명칭 데이터는 `npm run assets` 를 다시 돌리면
`source` 에 적은 언어로 채워집니다.

번역이 덜 끝난 언어도 그대로 굴러갑니다 — 빠진 문자열은 `fallback` 에 적은 언어를 거쳐
시트에 적힌 나머지 언어 순으로 읽고, 그 문자열이 쓰인 언어의 문법 규칙을 따릅니다. 그래서
영어로 대체된 문장에 한국어 조사 표기가 남는 일은 없습니다.

## 에리어

수록 에리어는 전부 3세대 호연 지방의 실제 맵입니다. 한 지방으로 통일한 이유는 화풍이
일관되기도 하지만, PokeAPI가 **호연 지역명의 공식 번역명을 가장 많은 언어로 가지고 있기
때문**입니다 (관동 지역명에는 한국어가 없습니다). 각 맵에서 통행 가능한 블록이 가장 많은 가로 띠를 골라
잘라낸 뒤, 좌우 반전본을 이어붙여 이음매 없이 순환하는 스크롤 배경으로 만듭니다.

어느 띠를 고르느냐는 통행 가능한 블록 수만 세면 안 됩니다 — 탁 트인 땅과 나무 울타리는
똑같이 "통행 가능"이라서, 그렇게 고르면 맵에서 가장 어수선한 구간이 뽑힙니다. 그래서 한 줄이
쓰는 **서로 다른 메타타일 수만큼 감점**해서, 실제로 길이 난 평범한 지형 쪽으로 기울입니다.
